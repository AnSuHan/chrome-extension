# 워크스페이스 전환 — 네이티브 탭 그룹 방식

## 배경 / 요구사항

전환(Open all)으로 워크스페이스를 오갈 때 다음을 **모두** 만족해야 한다.

1. **재로딩 없음** — 1번 → 2번 → 다시 1번으로 와도 1번 탭이 다시 로딩되면 안 됨.
2. **메모리 상한** — 워크스페이스가 쌓여도 메모리가 무한정 늘면 안 됨.
3. **추가 창/`about:blank` 없음** — 별도 브라우저 창이 뜨면 안 됨.
4. **Alt+Tab·작업표시줄에 의도치 않은 창이 안 보임.**
5. **여러 크롬 창에서도 정상 동작.**
6. **전환 전(이전) 워크스페이스의 탭이 보이지 않아야 함.**

### 왜 "스태시 창"이 아니라 "네이티브 탭 그룹"인가

탭을 **재로딩 없이 살려 두려면** 그 탭의 렌더러가 살아 있어야 하고, 살아 있는
탭은 반드시 **어떤 창엔가** 있어야 한다. 크롬 확장 API로는 **Alt+Tab/작업표시줄에
안 뜨는 창을 만들 수 없다**(최소화해도 Alt+Tab엔 나옴). 따라서 별도(스태시) 창
방식은 요구사항 3·4를 원리적으로 만족할 수 없다.

무재로딩을 유지하면서 3·4·5를 만족하는 유일한 방법은 탭을 **별도 창이 아니라
같은 창 안에** 살려 두는 것 = **네이티브 크롬 탭 그룹**이다. 대가로 탭 스트립에
**그룹 칩(색상 라벨)** 이 보이지만, 추가 창·Alt+Tab 흔적은 없다.

## 모델

- 창 안에 **로드된 워크스페이스 = 네이티브 탭 그룹** 하나.
- **활성 워크스페이스**의 그룹은 **펼침(expanded)**, 나머지 로드된 워크스페이스의
  그룹은 **접힘(collapsed)** → 탭이 숨겨지지만(칩만 남음) **로드 상태는 유지**.
- **전환** = 대상 그룹을 펼치고(있으면 재사용 → 무재로딩, 없으면 새로 열기),
  이전 그룹을 **접어서 탭이 안 보이게** 함(요구사항 6).
- **메모리 상한** = 창당 로드 워크스페이스 수를 `MAX_LOADED_WORKSPACES`(현재 3)로
  제한. 초과 시 가장 오래된(LRU) 워크스페이스의 탭을 닫아 메모리 회수(다음 전환
  때 lazy로 다시 열림).

## 구현 요약 (`src/background/service-worker.js`)

- **저장 상태**(storage.local, 창별 중첩 — 멀티 윈도우 지원):
  - `tabinet.active`   → `{ [windowId]: 활성 savedGroupId }`
  - `tabinet.wsgroups` → `{ [windowId]: { [savedGroupId]: nativeTabGroupId } }`
  - `tabinet.wsorder`  → `{ [windowId]: [savedGroupId, …] }` (MRU 앞, LRU 제거용)
  - 네이티브 그룹 id는 브라우저 상태라 서비스워커 재시작에도 살아남음.
    `chrome.tabGroups.get`으로 검증 후 사용(사용자가 수동 해제하면 자동 치유).
- `openWorkspaceGroup`: lazy 플레이스홀더 탭 생성 → `chrome.tabs.group`으로 묶고
  워크스페이스 이름/색으로 `tabGroups.update`(펼침).
- `switchToGroup`: (1) 대상 펼침/열기 + 첫 탭 활성화 → (2) 이전 그룹에 흩어진
  ungrouped 탭을 흡수 후 **접기** → (3) `MAX_LOADED_WORKSPACES` 초과분 evict →
  (4) 활성 워크스페이스 기록 + 창 포커스 유지.
- `adoptTabIntoActiveGroup`(onCreated): 새로 연 ungrouped 탭(Ctrl+T 등)을 활성
  워크스페이스 그룹에 편입 → 전환 시 함께 접혀 다음 워크스페이스로 새지 않음.
- `syncWorkspace`: **활성 그룹의 탭만** 저장 그룹에 미러링(접힌 워크스페이스는
  전환 당시 스냅샷 유지).
- `handleEmptiedWorkspace`: 활성 그룹 탭이 모두 닫히면 다른 로드된 워크스페이스를
  펼치거나(무재로딩), 없으면 다음 저장 그룹을 lazy로 열거나, 빈 탭 유지.
- `reconcileWorkspaces`(storage.onChanged, `tabinet.order` 변경 시): 삭제된
  그룹의 로드 탭을 모든 창에서 닫음(사이드바/에디터의 직접 삭제 대응).

### 사이드바 (`src/sidepanel/sidepanel.js`)

- 라이브 탭 목록을 **펼쳐진(현재 워크스페이스) 탭만** 보이도록 필터
  (`onlyVisibleTabs`): 접힌 그룹의 탭은 창에서도 안 보이므로 목록에서도 숨김.
- `tabGroups.onUpdated/onCreated/onRemoved`를 구독해 접힘/펼침 변화에 다시 렌더.

## 남은 정리·후속 과제 / 한계

1. **탭 스트립 그룹 칩**: 로드된 워크스페이스마다 색상 칩이 탭 스트립에 보인다.
   이는 "추가 창/Alt+Tab 흔적 없이 무재로딩"을 위한 불가피한 대가(요구사항 4의
   결과). 칩까지 없애려면 재로딩을 감수하는 수밖에 없음.
2. **메모리**: 로드된(최대 3개) 워크스페이스 탭은 메모리에 상주. 크롬 Memory
   Saver가 접힌 백그라운드 탭을 자체 discard하면 그때는 펼칠 때 재로딩될 수 있음
   (크롬 자체 동작). `MAX_LOADED_WORKSPACES`로 상한 조절.
3. **크롬 "저장된 탭 그룹"/동기화**: API로 만든 그룹은 기본적으로 임시(ephemeral)
   지만, 사용자가 탭 그룹 동기화를 켜 두면 북마크 바에 그룹이 나타날 수 있음
   (크롬 설정 영역, 확장이 완전 제어 불가). 필요 시 안내.
4. **첫 전환의 기존 탭**: 추적되지 않던 창에서 첫 Open all 시, 기존 ungrouped
   탭은 백업(`Backup —`) 후 정리됨(기존 스위치 semantics 유지).
5. **활성 그룹 "Reopen" 라벨**: 이미 활성인 그룹으로의 전환은 no-op(펼침만
   보장). 사이드바 라벨을 "Current" 등으로 바꾸는 정리 여지.
6. **`MAX_LOADED_WORKSPACES` 노출**: 현재 하드코딩. 옵션 페이지로 노출해 메모리
   vs 무재로딩 트레이드오프를 사용자가 조절하게 할 수 있음.
7. **restoreGroup(에디터 additive restore)**: ungrouped로 열리고 adoption에 의해
   현재 워크스페이스에 편입됨. 별도 취급이 필요하면 재검토.

## 수동 테스트 체크리스트

- [ ] 1번 열기 → 2번 Open all → 다시 1번 Open all: **1번 탭 재로딩 없이**
      스크롤/입력/로그인 상태 유지되는가?
- [ ] 전환 직후 **이전 워크스페이스 탭이 보이지 않는가**(그룹 접힘)?
- [ ] **Alt+Tab·작업표시줄에 추가 창이 전혀 없는가?** (`about:blank` 창 없음)
- [ ] 여러 크롬 창을 열어 각각 다른 워크스페이스로 전환해도 서로 간섭 없이
      독립 동작하는가?
- [ ] 활성 워크스페이스에서 Ctrl+T로 새 탭 → 그 탭이 워크스페이스에 편입되고,
      다른 워크스페이스로 전환하면 함께 숨는가?
- [ ] 4개 이상 워크스페이스를 순회하면 오래된 것은 evict(탭 닫힘, 다음에 lazy로
      다시 열림)되어 **메모리가 상한에서 안정**되는가?
- [ ] 로드된 워크스페이스를 사이드바/에디터에서 삭제하면 그 탭이 닫히는가?
- [ ] 활성 워크스페이스의 탭을 전부 닫으면 다른 로드된 워크스페이스로 재로딩 없이
      전환되는가(없으면 다음 저장 그룹 lazy)?
- [ ] 사이드바 라이브 목록에 **현재 워크스페이스 탭만** 보이는가(접힌 그룹 제외)?
