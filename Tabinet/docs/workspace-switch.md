# 워크스페이스 전환 — 네이티브 탭 그룹 방식

## 배경 / 요구사항

전환(Open all)으로 워크스페이스를 오갈 때 다음을 **모두** 만족해야 한다.

1. **재로딩 없음** — 1번 → 2번 → 다시 1번으로 와도 1번 탭이 다시 로딩되면 안 됨.
2. **메모리 상한** — 워크스페이스가 쌓여도 메모리가 무한정 늘면 안 됨.
3. **추가 창/`about:blank` 없음** — 별도 브라우저 창이 뜨면 안 됨.
4. **Alt+Tab·작업표시줄에 의도치 않은 창이 안 보임.**
5. **여러 크롬 창에서도 정상 동작.**
6. **전환 전(이전) 워크스페이스의 탭이 보이지 않아야 함.**

### 왜 "스태시 창"이 아니라 "네이티브 탭 그룹"인가

탭을 **재로딩 없이 살려 두려면** 그 탭의 렌더러가 살아 있어야 하고, 살아 있는
탭은 반드시 **어떤 창엔가** 있어야 한다. 크롬 확장 API로는 **Alt+Tab/작업표시줄에
안 뜨는 창을 만들 수 없다**(최소화해도 Alt+Tab엔 나옴). 따라서 별도(스태시) 창
방식은 요구사항 3·4를 원리적으로 만족할 수 없다.

무재로딩을 유지하면서 3·4·5를 만족하는 유일한 방법은 탭을 **별도 창이 아니라
같은 창 안에** 살려 두는 것 = **네이티브 크롬 탭 그룹**이다. 대가로 탭 스트립에
**그룹 칩(색상 라벨)** 이 보이지만, 추가 창·Alt+Tab 흔적은 없다.

## 모델

- 창 안에 **로드된 워크스페이스 = 네이티브 탭 그룹** 하나.
- **활성 워크스페이스**의 그룹은 **펼침(expanded)**, 나머지 로드된 워크스페이스의
  그룹은 **접힘(collapsed)** → 탭이 숨겨지지만(칩만 남음) **로드 상태는 유지**.
- **전환** = 대상 그룹을 펼치고(있으면 재사용 → 무재로딩, 없으면 새로 열기),
  이전 그룹을 **접어서 탭이 안 보이게** 함(요구사항 6).
- **메모리 상한** = 창당 로드 워크스페이스 수를 `MAX_LOADED_WORKSPACES`(현재 3)로
  제한. 초과 시 가장 오래된(LRU) 워크스페이스의 탭을 닫아 메모리 회수(다음 전환
  때 lazy로 다시 열림).

## 구현 요약 (`src/background/service-worker.js`)

- **저장 상태**(storage.local, 창별 중첩 — 멀티 윈도우 지원):
  - `tabinet.active`   → `{ [windowId]: 활성 savedGroupId }`
  - `tabinet.wsgroups` → `{ [windowId]: { [savedGroupId]: nativeTabGroupId } }`
  - `tabinet.wsorder`  → `{ [windowId]: [savedGroupId, …] }` (MRU 앞, LRU 제거용)
  - 네이티브 그룹 id는 브라우저 상태라 서비스워커 재시작에도 살아남음.
    `chrome.tabGroups.get`으로 검증 후 사용(사용자가 수동 해제하면 자동 치유).
- `openWorkspaceGroup`: lazy 플레이스홀더 탭 생성 → `chrome.tabs.group`으로 묶고
  워크스페이스 이름/색으로 `tabGroups.update`(펼침).
- `switchToGroup`: (1) 대상 펼침/열기 + 첫 탭 활성화 → (2) 이전 그룹에 흩어진
  ungrouped 탭을 흡수 후 **접기** → (3) `MAX_LOADED_WORKSPACES` 초과분 evict →
  (4) 활성 워크스페이스 기록 + 창 포커스 유지.
- `adoptTabIntoActiveGroup`(onCreated): 새로 연 ungrouped 탭(Ctrl+T 등)을 활성
  워크스페이스 그룹에 편입 → 전환 시 함께 접혀 다음 워크스페이스로 새지 않음.
- `syncWorkspace`: **활성 그룹의 탭만** 저장 그룹에 미러링(접힌 워크스페이스는
  전환 당시 스냅샷 유지).
- `handleEmptiedWorkspace`: 활성 그룹 탭이 모두 닫히면 다른 로드된 워크스페이스를
  펼치거나(무재로딩), 없으면 다음 저장 그룹을 lazy로 열거나, 빈 탭 유지.
- `reconcileWorkspaces`(storage.onChanged, `tabinet.order` 변경 시): 삭제된
  그룹의 로드 탭을 모든 창에서 닫음(사이드바/에디터의 직접 삭제 대응).

### 전환 시 백그라운드 프리워밍 (`src/background/prewarm.js`)

전환 자체는 lazy 플레이스홀더 덕에 즉시 끝나지만, **첫 클릭**이 DNS/TLS + 로그인
리다이렉트 체인(앱 → SSO → 앱) + 문서 다운로드를 한꺼번에 부담한다. 그래서
워크스페이스가 화면에 들어오는 순간, **서비스워커가 그 워크스페이스의 아직 안
열린 페이지들을 조용히 요청**해 둔다(`credentials: "include"`, 리다이렉트 추적).

- 렌더링은 하지 않는다. 노리는 것은 클릭이 기다리게 될 **부수효과**:
  세션/인증 쿠키가 이미 쿠키 항아리에 들어와 있고(→ 클릭하면 리다이렉트 체인을
  다시 돌지 않고 바로 로그인된 화면), 호스트 DNS/TLS가 풀려 있고, HTML 문서가
  HTTP 캐시에 있다.
- 대상은 **플레이스홀더 상태인 탭의 실제 url만** (`pendingUrls`). 이미 진짜
  페이지가 떠 있는 탭이나 방금 활성화해 스스로 로딩을 시작한 탭은 제외한다.
- 안전장치: 동시 3개, 페이지당 20초 타임아웃, 같은 url은 3분 TTL로 재요청 억제,
  1회 최대 24개. html 이 아니면 헤더만 받고 중단(PDF/설치파일 통째 다운로드 방지).
- **창별 키**(`win:<windowId>`)로 실행되어, 다시 전환하면 이전 워크스페이스의
  워밍은 즉시 취소된다. 창을 닫아도 취소.
- 실패는 전부 무시(오프라인·차단·타임아웃). 전환은 **절대 네트워크를 기다리지
  않는다** (fire-and-forget).
- 호출 지점: `switchToGroup`(대상 펼침/열기 직후, 이미 활성인 그룹 재클릭 포함),
  `handleEmptiedWorkspace`(대체 워크스페이스 펼침/열기 직후).
- **manifest `host_permissions: ["http://*/*", "https://*/*"]` 필요.** 호스트 권한
  없이는 워커의 교차 출처 인증 fetch 가 차단된다(= 워밍 효과 없음). 기존 설치본은
  업데이트 시 사용자가 권한을 다시 승인해야 한다.

### 북마크바 노출 제어 (전체 on/off + 그룹별)

**증상**: 북마크바에 `Untitled group`, `Backup — …` 같은 **탭 그룹 칩**이 쌓인다.
이는 크롬의 **"저장된 탭 그룹(saved tab groups)"** 기능이다. Tabinet 이 만든
네이티브 탭 그룹을 크롬이 자동 저장해 북마크바에 나열하는 것.

**확장 API 로는 직접 못 끈다.** `chrome.tabGroups` 는 현재 살아 있는 그룹만
다루고, 저장된 그룹(북마크바 항목)에 접근하는 API 자체가 없다. 그래서 제어할 수
있는 유일한 레버는 **"애초에 네이티브 탭 그룹을 만들/남길 것인가"** 다.

1. **칩이 쌓이던 원인 제거 (`closeWorkspaceTabs` / `unloadWorkspace`)**
   그룹의 탭을 그냥 `tabs.remove` 하면 크롬에게는 **"그룹 닫기"** = 저장된 그룹이
   남아 칩이 영구히 북마크바에 박힌다. 그래서 **닫기 전에 `tabs.ungroup` 으로 그룹을
   먼저 해체**한다(= UI 의 "그룹 해제", 저장 안 됨). evict·삭제·언로드 모두 적용.
2. **설정 (`storage.js`)**
   - 전역: `settings.keepLoaded` (기본 `true`)
   - 그룹별: 그룹 레코드의 `keepLoaded` (`true`/`false`, 없으면 전역을 따름)
   - `resolveKeepLoaded(group, settings)` 가 최종 판정.
3. **`keepLoaded = false` 인 워크스페이스는 탭 그룹을 아예 안 만든다.**
   - 열 때: `openWorkspaceGroup(..., { grouped: false })` → 평범한 탭으로만 열림
     (탭 스트립 칩도, 북마크바 칩도 없음).
   - 전환해 나갈 때: `unloadWorkspace` 가 **현재 화면 내용을 저장 그룹에 스냅샷한 뒤**
     (전환 중에는 live-sync 가 멈춰 있으므로 이때가 마지막 기회) 탭을 닫는다.
     복귀 시 lazy 로 다시 열리고, 프리워밍이 붙어 체감 지연이 작다.
   - 그룹 없이 도는 워크스페이스는 기존 "gid == null" 경로(`syncWorkspace`,
     `activeWorkspaceTabCount`, `adoptTabIntoActiveGroup`)가 그대로 처리한다.
4. **전환 순서 주의 (`switchToGroup` 0단계)**
   대상이 ungrouped 로 열릴 수 있게 되면서, "창의 ungrouped 탭 = 이전 워크스페이스"
   라는 기존 가정이 깨진다. 그래서 **대상 탭을 만들기 전에** 이전 워크스페이스의
   탭(그룹 탭 + 현재 ungrouped 탭)을 먼저 캡처해 두고, 그 목록으로 접기/닫기를
   수행한다. (닫기를 먼저 할 수는 없다 — 창의 마지막 탭을 닫으면 창이 닫힌다.)
5. **`withSwitchGuard`**: ungroup → remove 사이 찰나에 탭이 ungrouped 로 보이므로,
   live-sync 가 그걸 활성 워크스페이스의 탭으로 오인해 덮어쓰지 않도록 창을
   전환 중으로 표시한다(중첩 안전).

**남는 한계**: `keepLoaded = true` 이면 **현재 활성 워크스페이스의 그룹 칩은
반드시 보인다**(살아 있는 그룹이므로). 칩을 완전히 없애려면 전역 off, 또는
크롬 자체 설정 — **북마크바 우클릭 → "탭 그룹 표시" 해제**. 이미 쌓인 옛 칩은
크롬이 계속 저장하고 있으므로 **우클릭 → 삭제로 한 번만 정리**해야 한다.

**UI (`src/manager/`)**: 사이드바 하단에 전역 체크박스
"Keep workspaces live in the background" + 크롬 설정 안내 문구, 그룹 상세 헤더에
`Default (…) / Keep live / Close on switch` 셀렉터.

### 사이드바 (`src/sidepanel/sidepanel.js`)

- 라이브 탭 목록을 **펼쳐진(현재 워크스페이스) 탭만** 보이도록 필터
  (`onlyVisibleTabs`): 접힌 그룹의 탭은 창에서도 안 보이므로 목록에서도 숨김.
- `tabGroups.onUpdated/onCreated/onRemoved`를 구독해 접힘/펼침 변화에 다시 렌더.

## 남은 정리·후속 과제 / 한계

1. **탭 스트립 그룹 칩**: 로드된 워크스페이스마다 색상 칩이 탭 스트립에 보인다.
   이는 "추가 창/Alt+Tab 흔적 없이 무재로딩"을 위한 불가피한 대가(요구사항 4의
   결과). 칩까지 없애려면 재로딩을 감수하는 수밖에 없음.
2. **메모리**: 로드된(최대 3개) 워크스페이스 탭은 메모리에 상주. 크롬 Memory
   Saver가 접힌 백그라운드 탭을 자체 discard하면 그때는 펼칠 때 재로딩될 수 있음
   (크롬 자체 동작). `MAX_LOADED_WORKSPACES`로 상한 조절.
3. **크롬 "저장된 탭 그룹"(북마크바 칩)**: 확장 API로 저장된 그룹을 지우거나 숨길
   수 없다. 위 "북마크바 노출 제어" 절에서 (a) 닫을 때 ungroup 해 칩이 쌓이지
   않게 하고, (b) `keepLoaded` off 로 탭 그룹 자체를 안 만들게 하는 것까지가
   확장이 할 수 있는 전부. 활성 워크스페이스 칩 제거·기존 칩 정리는 크롬 UI 몫.
4. **첫 전환의 기존 탭**: 추적되지 않던 창에서 첫 Open all 시, 기존 ungrouped
   탭은 백업(`Backup —`) 후 정리됨(기존 스위치 semantics 유지).
5. **활성 그룹 "Reopen" 라벨**: 이미 활성인 그룹으로의 전환은 no-op(펼침만
   보장). 사이드바 라벨을 "Current" 등으로 바꾸는 정리 여지.
6. **`MAX_LOADED_WORKSPACES` 노출**: 현재 하드코딩. 옵션 페이지로 노출해 메모리
   vs 무재로딩 트레이드오프를 사용자가 조절하게 할 수 있음.
7. **restoreGroup(에디터 additive restore)**: ungrouped로 열리고 adoption에 의해
   현재 워크스페이스에 편입됨. 별도 취급이 필요하면 재검토.

## 수동 테스트 체크리스트

- [ ] 1번 열기 → 2번 Open all → 다시 1번 Open all: **1번 탭 재로딩 없이**
      스크롤/입력/로그인 상태 유지되는가?
- [ ] 전환 직후 **이전 워크스페이스 탭이 보이지 않는가**(그룹 접힘)?
- [ ] **Alt+Tab·작업표시줄에 추가 창이 전혀 없는가?** (`about:blank` 창 없음)
- [ ] 여러 크롬 창을 열어 각각 다른 워크스페이스로 전환해도 서로 간섭 없이
      독립 동작하는가?
- [ ] 활성 워크스페이스에서 Ctrl+T로 새 탭 → 그 탭이 워크스페이스에 편입되고,
      다른 워크스페이스로 전환하면 함께 숨는가?
- [ ] 4개 이상 워크스페이스를 순회하면 오래된 것은 evict(탭 닫힘, 다음에 lazy로
      다시 열림)되어 **메모리가 상한에서 안정**되는가?
- [ ] 로드된 워크스페이스를 사이드바/에디터에서 삭제하면 그 탭이 닫히는가?
- [ ] 활성 워크스페이스의 탭을 전부 닫으면 다른 로드된 워크스페이스로 재로딩 없이
      전환되는가(없으면 다음 저장 그룹 lazy)?
- [ ] 사이드바 라이브 목록에 **현재 워크스페이스 탭만** 보이는가(접힌 그룹 제외)?
- [ ] 로그인이 필요한 사이트가 든 워크스페이스로 전환 → 몇 초 두었다가 탭 클릭:
      로그인 리다이렉트를 눈으로 거의 못 볼 만큼 빨리 로그인된 화면이 뜨는가?
      (서비스워커 콘솔·`chrome://net-export` 또는 서버 액세스 로그로 전환 시점에
      요청이 나갔는지 확인 가능)
- [ ] 전환하자마자 곧바로 다른 워크스페이스로 다시 전환 → 이전 워밍이 취소되어
      네트워크가 계속 물고 있지 않은가?
- [ ] 전역 "Keep workspaces live in the background" **끄기** → 전환 시 이전
      워크스페이스 탭이 저장 후 닫히고, **탭 스트립·북마크바에 그룹 칩이 전혀
      생기지 않는가?** (기존에 쌓인 칩은 크롬에서 수동 삭제 후 확인)
