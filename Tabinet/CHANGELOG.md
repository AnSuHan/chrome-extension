# 변경 이력 (Changelog)

Tabinet 의 모든 주요 변경 사항을 기록합니다.

- 버전 체계: [유의적 버전(SemVer)](https://semver.org/lang/ko/) `vMAJOR.MINOR.PATCH`
  - MAJOR — 호환이 깨지는 변경(저장 포맷·동작 방식의 비호환 변경)
  - MINOR — 호환을 유지하는 기능 추가
  - PATCH — 버그 수정·소규모 개선
- 각 항목은 **사용자가 체감하는 변화**를 먼저 적습니다.
- `manifest.json` 의 `version` 과 이 문서의 최신 버전은 항상 일치시킵니다.

## [Unreleased]

### 개선

**자동 저장 옵션 2개 (개별 on/off)**
- **Auto-save where tabs navigate** — 활성 워크스페이스의 탭이 다른 페이지로
  이동하면 저장된 워크스페이스의 그 자리도 따라 갱신된다(기본 켬). 끄면 저장된
  탭은 저장 당시 URL 을 유지한다.
- **Auto-save tabs you add or close** — 탭을 새로 열거나 닫으면 저장된
  워크스페이스의 **탭 개수**도 따라 바뀐다(기본 켬). 끄면 저장 당시 탭 개수를
  유지하고, 위 옵션이 켜져 있으면 각 탭이 어디로 갔는지만 반영한다.
- 둘 다 끄면 저장본이 동결되어, 직접 다시 저장하기 전에는 바뀌지 않는다.
- 두 옵션은 **워크스페이스를 닫으며 저장할 때**(keep-live 끈 상태의 전환)도
  똑같이 적용된다.
- 기본값은 둘 다 켬 = 기존 동작 그대로.

**클릭 시 cold loading 제거 (탭 하이드레이션)**
- 워크스페이스를 열면 그 창의 탭들을 **백그라운드에서 실제로 로딩**한다(동시 3개,
  1회 최대 60탭). 클릭하는 순간에는 이미 렌더까지 끝난 페이지가 떠 있어,
  플레이스홀더 화면이나 로딩 대기가 보이지 않는다.
- 플레이스홀더가 **스스로** `location.replace` 로 이동하므로(워커가 포트로 신호를
  보냄), 히스토리에 플레이스홀더가 남지 않아 **Back 이 튕기지 않는다.**
- **열려 있는 탭만** 대상으로 한다. 저장돼 있지만 탭으로 열려 있지 않은 url 에는
  아무 요청도 나가지 않는다(기존 "저장 url 프리워밍 폴백" 제거).
- 모든 작업이 **창 하나 안에서만** 일어난다. 새 창을 만들지 않고, 다른 창의 탭도
  건드리지 않는다. 편집기의 additive restore(`restoreGroup`)도 대상 창을 명시해
  한 창에 모아 연다.
- 1회 상한(60탭)을 넘는 초과분은 기존 네트워크 프리워밍이 맡아 세션/DNS/문서
  캐시를 데운다.
- 다른 워크스페이스로 전환하면 이전 워크스페이스의 백그라운드 로딩은 즉시 취소된다.
- 새 설정 **Pre-load tabs when a workspace opens**(편집기, 기본 켜짐). 끄면 예전
  동작(클릭할 때 로딩 + 네트워크 프리워밍만).

## [1.0.0] — 2026-08-15

첫 정식 버전. 사이드 패널 · 워크스페이스 전환 · 저장/편집/동기화까지 한 벌로
동작하는 상태를 1.0.0 으로 확정했습니다.

### 주요 기능

**사이드 패널 (Safari 스타일 사이드바)**
- 툴바 아이콘 클릭으로 브라우저 옆에 고정. 보던 페이지를 계속 쓰면서 조작.
- **Save window** — 현재 창의 http(s) 탭 전체를 이름·색이 있는 그룹으로 저장.
- **Save group** — 활성 탭이 속한 크롬 탭 그룹만, 이름과 색 그대로 저장.
  같은 이름 + 같은 url 집합이면 중복 저장하지 않음.
- **New group (+)** — 빈 그룹을 만들어 채우기.
- **라이브 열린 탭 목록** — 현재 워크스페이스의 탭만 보여줌.
- 이름 더블클릭으로 즉시 이름 변경, 색 점 클릭으로 팔레트, 탭 추가·삭제·드래그
  정렬 및 다른 그룹으로 이동.

**워크스페이스 전환 (Open all)**
- 저장 그룹을 창의 **활성 워크스페이스**로 전환. 이전 워크스페이스는 화면에서
  사라지고, 되돌아오면 그대로 이어서 씀.
- **무재로딩** — 전환해 나간 워크스페이스는 네이티브 탭 그룹으로 살아 있어(접힘),
  다시 돌아올 때 재로딩·재로그인이 없음.
- **추가 창 없음** — 별도 브라우저 창을 만들지 않아 Alt+Tab·작업표시줄이 깨끗함.
- **메모리 상한** — 창당 살아 있는 워크스페이스를 3개로 제한(LRU). 초과분은 탭을
  닫아 회수하고, 다음에 돌아올 때 다시 열림.
- **지연(lazy) 탭** — 복원된 탭은 실제 URL 대신 로컬 플레이스홀더로 즉시 열리고,
  처음 볼 때 진짜 URL 로 이동. 큰 워크스페이스도 순식간에 열림.
- **라이브 동기화** — 활성 워크스페이스에서 이동·열기·닫기·정렬한 결과가 저장
  그룹에 그대로 반영(로그인 흐름이 최종 도착한 URL 포함).
- 활성 워크스페이스의 탭을 전부 닫아도 창이 닫히지 않고 다른 워크스페이스로 이어짐.

**전환 시 백그라운드 프리워밍** *(신규)*
- 워크스페이스가 화면에 들어오는 순간, 아직 안 열린 페이지들을 백그라운드에서 미리
  요청해 둠 → **탭을 눌렀을 때 로그인 리다이렉트를 거의 못 느낄 만큼 빨리** 열림.
- 세션·인증 쿠키, DNS/TLS, 문서 캐시를 미리 데워 두는 것이 목적(화면 렌더링 없음).
- 아직 안 열린 탭만 대상. 동시 3개 / 페이지당 20초 / 같은 주소 3분 내 재요청 안 함 /
  1회 최대 24개 / HTML 이 아니면 헤더만 받고 중단.
- 다른 워크스페이스로 다시 전환하면 진행 중이던 워밍은 즉시 취소.
- 이를 위해 **호스트 권한(`http://*/*`, `https://*/*`)** 이 추가됨. 저장해 둔 주소만
  요청하며, 데이터는 어디로도 전송되지 않음.

**북마크바 탭 그룹 노출 제어** *(신규)*
- 크롬은 살아 있는 탭 그룹을 **북마크바에 칩으로 나열**합니다. 이제 이를 조절 가능:
  - **전체 on/off** — 편집기 사이드바 하단 "Keep workspaces live in the background".
    끄면 Tabinet 이 탭 그룹을 **아예 만들지 않아** 탭 스트립·북마크바에 아무것도
    남지 않음(대신 전환해 돌아올 때 다시 열림 — 프리워밍이 붙어 체감 지연은 작음).
  - **그룹별 개별 설정** — 그룹 상세 헤더의 `Default / Keep live / Close on switch`.
- 워크스페이스를 닫을 때 **그룹을 먼저 해체(ungroup)** 하도록 변경 → 정리된
  워크스페이스의 칩이 북마크바에 계속 쌓이던 문제 해결.

**저장 · 백업 · 동기화**
- 기본은 `chrome.storage.local` (기기 내 저장, 외부 전송 없음).
- **Sync across devices** — `chrome.storage.sync` 로 전환해 로그인된 모든 크롬에서
  공유. 용량 초과 시 전환을 중단하고 기존 데이터를 그대로 유지.
- **Save JSON / Load JSON** — 전체 그룹 내보내기, **Merge**(추가) / **Replace all**
  (전체 교체) 두 방식으로 가져오기.
- 그룹은 인덱스 + 그룹별 항목으로 **샤딩 저장**(sync 의 항목당 용량 제한 대응).

**전체 편집기 (옵션 페이지)**
- 좌: 전체 그룹 목록(선택·생성·삭제·드래그 정렬), 우: 선택한 그룹의 탭 편집
  (제목/URL 인라인 수정, 정렬, 추가/삭제, 다른 그룹으로 드래그 이동).

### 요구 사항
- Chrome 114 이상 (Side Panel API)
- 권한: `tabs`, `tabGroups`, `storage`, `downloads`, `sidePanel`,
  호스트 권한 `http://*/*`, `https://*/*`

### 알려진 제한
- **활성 워크스페이스의 그룹 칩은 북마크바에 계속 보입니다.** 살아 있는 탭 그룹은
  크롬이 항상 나열하며, 확장 API 로 저장된 탭 그룹을 숨기거나 지울 수 없습니다.
  완전히 없애려면 전체 설정을 끄거나, **북마크바 우클릭 → "탭 그룹 표시" 해제**.
- **이전 버전에서 이미 쌓인 칩**은 크롬이 계속 저장하고 있으므로, 한 번은
  **우클릭 → 삭제**로 직접 정리해야 합니다.
- 프리워밍 효과는 사이트마다 다릅니다(캐시 금지 응답, 클라이언트 측에서만 인증을
  처리하는 SPA 등에서는 체감이 작을 수 있음).
- 크롬 메모리 세이버가 접힌 백그라운드 탭을 스스로 폐기하면, 그 워크스페이스는
  돌아올 때 재로딩될 수 있습니다(크롬 자체 동작).
- `chrome.storage.sync` 는 용량이 작습니다(≈100KB). 그룹이 많으면 로컬 유지 권장.
- **크롬 버전별 실측 필요**: (1) 닫기 전 ungroup 이 모든 크롬 버전에서 저장된 그룹
  칩을 남기지 않는지, (2) 프리워밍 요청이 대상 사이트의 인증 쿠키를 함께 실어
  보내는지. 수동 확인 절차는 `docs/workspace-switch.md` 체크리스트 참고.
